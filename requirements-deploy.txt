# Deployment dependencies for the live app (app/ + the retrieval/rerank/
# generation modules it imports from scripts/). Deliberately separate from
# requirements.txt, which is the full research environment (langchain,
# llama-index, ragas, ir_datasets, google-cloud-*, CUDA torch, etc.) --
# none of that is imported by anything the deployed app actually runs.
#
# torch/torchvision/torchaudio are CPU-only builds, installed from
# PyTorch's own CPU wheel index (see Dockerfile) -- NOT the +cu128 CUDA
# build requirements.txt pins for the research GPU environment. Verified
# against the official PyTorch "previous versions" install page
# (https://pytorch.org/get-started/previous-versions/) before pinning:
# the CPU wheel pattern is
#   pip install torch==<ver> torchvision==<ver> torchaudio==<ver> \
#       --index-url https://download.pytorch.org/whl/cpu
# so torch/torchvision/torchaudio are intentionally NOT listed here --
# the Dockerfile installs them in a separate step with that index, and
# listing them again here with no index could make pip try to resolve a
# different (CUDA) build from the default index.
#
# Versions below are exactly what this project has already run against
# throughout development (pinned from the working venv), not guesses.
